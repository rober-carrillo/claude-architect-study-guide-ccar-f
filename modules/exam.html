About the 720

720 is a scaled score, so it doesn't mean "72% correct". Scaling evens out different exam forms, and the raw-to-scaled mapping isn't published. For practice, aim for 80%+ on fresh questions to leave margin.

Not on the exam

Fine-tuning; API authentication, OAuth, key rotation, billing; rate limits and pricing calculations; hosting MCP servers; streaming/SSE; computer use; vision; embeddings and vector DBs; cloud-provider setup; benchmarking; tokenization; prompt-caching details beyond knowing it exists; Claude's training, RLHF, Constitutional AI.

Scenario 1

Customer Support Resolution Agent

An Agent SDK agent handles ambiguous returns, billing disputes and account issues through MCP tools get_customer, lookup_order, process_refund and escalate_to_human. The target is 80%+ first-contact resolution while knowing when to escalate.

Agentic architecture · Tool design & MCP · Context & reliability

What they probe

  • Agent skips get_customer and refunds the wrong account → a programmatic prerequisite that blocks lookup_order/process_refund until a verified ID exists
  • Wrong tool picked between two similar ones → better descriptions first
  • Escalates easy cases and tackles policy exceptions → explicit escalation criteria + few-shot examples (not confidence scores, not sentiment)
  • Refunds over $500 → hook that blocks and redirects to escalation
  • Message with three separate complaints → split into items, investigate each, then give one unified reply
  • Handoff to a human who can't see the transcript → structured summary: customer ID, root cause, amount, recommended action
  • Long chat loses amounts and order numbers → persistent case facts block; trim the 40-field order lookups

Scenario 2

Code Generation with Claude Code

A team uses Claude Code for generation, refactoring, debugging and docs. It needs custom slash commands, CLAUDE.md configuration, and a sense of when to use plan mode versus direct execution.

Claude Code config · Context & reliability

What they probe

  • Shared /review command → .claude/commands/ in the repo (not ~/.claude/commands/, not CLAUDE.md, not a made-up config.json)
  • Monolith to microservices → plan mode from the start, because the complexity is already known
  • Test files scattered next to source → .claude/rules/ with a **/*.test.tsx glob, not a CLAUDE.md per directory
  • New teammate missing conventions → they were in user-level CLAUDE.md; check with /memory
  • Prose instructions read inconsistently → 2–3 concrete input/output examples
  • Long session starts saying "typical patterns" instead of naming real classes → scratchpad file, /compact, Explore subagent

Scenario 3

Multi-Agent Research System

A coordinator delegates to four subagents: web search, document analysis, synthesis and report generation. It produces comprehensive, cited reports.

Agentic architecture · Tool design & MCP · Context & reliability

What they probe

  • Report covers only part of the topic while every subagent did its job → the coordinator's decomposition was too narrow
  • Subagent times out → return structured error context (failure type, query tried, partial results, alternatives)
  • Synthesis keeps bouncing to the coordinator for simple fact checks → a scoped verify_fact tool for the common case; complex checks still go through the coordinator
  • Slow pipeline → several Task calls in one coordinator turn
  • Citations lost in synthesis → structured claim–source mappings carried through every step
  • Two credible sources disagree → keep both, attributed; don't pick one
  • Coordinator needs "Task" in allowedTools

Scenario 4

Developer Productivity with Claude

An Agent SDK tool helps engineers explore unfamiliar codebases, understand legacy systems, generate boilerplate and automate chores, using built-in tools (Read, Write, Bash, Grep, Glob) and MCP servers.

Tool design & MCP · Claude Code config · Agentic architecture

What they probe

  • Grep searches file contents (callers, error strings). Glob finds files by name pattern.
  • Edit fails when its anchor text isn't unique → fall back to Read + Write
  • Understanding a codebase: Grep for entry points, then Read along imports. Don't read everything upfront.
  • Agent prefers Grep over a better MCP tool → improve the MCP tool's description
  • Standard integration like Jira → use the community MCP server; build custom only for team-specific work
  • Agent keeps probing to learn what exists → expose a catalog as an MCP resource
  • "Add tests to a legacy codebase" → map the structure, find high-impact areas, then follow a plan that adapts

Scenario 5

Claude Code for Continuous Integration

Claude Code runs in CI/CD for automated review, test generation and PR feedback. Prompts must give actionable feedback and keep false positives low.

Claude Code config · Prompt engineering & structured output

What they probe

  • Job hangs → -p. The distractors CLAUDE_HEADLESS, --batch and < /dev/null don't exist or don't work.
  • Machine-readable findings → --output-format json + --json-schema
  • 14-file PR reviewed unevenly → a pass per file, then a cross-file integration pass
  • Duplicate comments after new commits → include prior findings; report only new or unresolved issues
  • False positives → explicit criteria; temporarily disable the noisy category
  • Cost cut proposal → Batch for the overnight report, synchronous for the pre-merge gate
  • Self-review is weak → use an independent instance

Scenario 6

Structured Data Extraction

Extract information from unstructured documents, validate it with JSON schemas, keep accuracy high, handle edge cases and feed downstream systems.

Prompt engineering & structured output · Context & reliability

What they probe

  • Reliable JSON → extraction tool + tool_use. Use "any" when the document type is unknown, and forced tool choice to make one extraction run first.
  • Made-up values → nullable fields; enum with "unclear", or "other" + a detail field
  • Totals don't add up → calculated_total next to stated_total, a conflict_detected flag, and a retry that includes the specific error
  • Retry won't help when the data isn't in the document
  • Varied layouts (inline citations vs bibliography) → few-shot examples of each
  • 97% overall can hide a bad document type → measure accuracy by type and field; stratified sampling
  • Batch failures → resubmit by custom_id, splitting oversized documents into chunks
How to read a scenario question
  • "Most effective first step" means the cheapest change that fixes the root cause. A routing classifier, an ML model or a bigger model is usually the over-engineered distractor.
  • "Guarantee" or "must never" points to code: a hook, a prerequisite gate or a deny rule. Without that wording, a better prompt or few-shot examples are usually fine.
  • Read the logs in the question. The official sample questions put the root cause in the evidence ("the coordinator decomposed into digital art, graphic design, photography").
  • When several downstream components "work correctly", the fault is upstream.
Exam

How to answer scenario questions

Almost every option is plausible. These patterns help you eliminate the wrong ones quickly.

Read the question's key word first

WordingWhat it's asking for
"most effective first step"The cheapest change that addresses the root cause. Not the most complete redesign.
"most likely root cause"Read the evidence in the stem (logs, decomposition, config); the answer is usually in it. If downstream parts "work correctly", look upstream.
"guarantee", "must never", "every time", financial or legal consequencesDeterministic code: a hook, prerequisite gate, permission rule or schema.
"most maintainable"The option that applies automatically and scales (glob rules, project config) over manual or per-person setups.
"available to every developer"Project scope, committed to the repo.

Time management

  • 2 minutes per item. At 30 minutes you should be around item 15, at 60 around 30, and at 90 around 45.
  • Flag and move on after about 90 seconds. Candidates report changing about half of their flagged answers on review, because later questions jog their memory.
  • Multiple-response: decide each option on its own (true or false for this scenario), then check that the count matches.
